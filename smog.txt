6. BUGS FOUND AND FIXED
--------------------------------------------------------------------------------
FIX 1 — e2e asserted the wrong HUD active class.
  Symptom: "HUD Vision captures a screen frame" and the Screen-tab check failed
  even though capture worked.
  Cause: probes used className.includes('text-emerald-300'); HudAction's active
  tone is 'bg-rose-500/20 text-rose-200 border-rose-500/40'
  (src/renderer/src/components/HudBar.tsx:19-23).
  Fix: replaced all 5 occurrences in scripts/e2e.mjs with 'text-rose-200'.
  Diagnosis method: temporary [dbg] console.log in onVision + captureFrame,
  collected via CDP Runtime.consoleAPICalled — proved
  "onVision enter -> captureFrame enter -> captureFrame ok" fired on both the
  native click and the direct props.onClick() call (harness instrumentation was
  later fully removed; 0 leftovers).

FIX 2 — first-run settings modal flaky on slow startup.
  e2e bailed out as soon as #apiKey/#model were absent (1500 ms after launch),
  producing "first-run settings modal saves config" + "base URL defaults..." +
  ENOENT config.json failures.
  Fix: poll for #apiKey/#model up to 30 x 250 ms before deciding
  "modal:false"; verify with node --check.

FIX 3 — NSIS packaging failed with disk-space error.
  Symptom: "Error: can't write 67108864 bytes to output" when the Windows target
  included both x64 and arm64.
  Fix: cleaned release/ and built x64 only; arm64 documented as a CLI flag
  (npx electron-builder --win --arm64 --publish never).

FIX 4 — scripts/e2e.mjs truncated to 0 bytes.
  Cause: a failed FileSystem.writeFile during an edit.
  Fix: file restored (currently 768 lines) and re-validated with `node --check`.

FIX 5 — temporary debug scaffolding removed.
  Removed: [dbg] console.log from store.tsx captureFrame and HudBar onVision,
  CDP events array + Runtime.enable in e2e connect(), React source dump,
  props-identity probe, frame poll, direct screen:capture probe,
  "renderer debug console" record.
  Kept (real improvements): setup-modal wait loop, screenUi detail output
  (cards/frame/age/visionOk).

FIX 6 — typecheck hygiene.
  structure.ts: removed unused local `codes`
  prompts.ts: removed dead `screenMessages`
  store.tsx: removed stale `askScreen` from StoreValue
  -> `npm run typecheck` clean (typecheck:node + typecheck:web).

FIX 7 — e2e mock answer enriched with "## Introduction / ## Content /
  ## Conclusion" headings so the Structure-card assertions (3/3 sections) pass.

FIX 8 — HUD/Auto-Pilot title-bar buttons broke the overlay e2e check.
  Symptom: run stopped at check 8 with "Cannot read properties of null
  (reading 'click')" from scripts/e2e.mjs:319.
  Cause: the button title was changed to "Toggle stealth overlay window
  (Ctrl+Shift+H / Cmd+Shift+H)" while the probe still selects
  button[title="Toggle stealth overlay window"].
  Fix: restored the exact title; shortcut hints moved to aria-keyshortcuts
  (also on the Auto-Pilot button). Re-ran e2e -> 31/31.

FIX 9 — HUD window must never auto-open (preventive).
  e2e picks the main window with !t.url.includes('window=overlay'), so any extra
  page target at boot could be mistaken for the main window.
  Fix: createHudWindow runs only from hud:toggle (and is never called during
  boot); allWindows() includes it afterwards for move/dock/focus handling.

CONSTRAINT (do not regress) — scripts/check-worklet.cjs requires the literal
  "const WORKLET_SOURCE = ` " plus the ${MIN_CHUNK_SECONDS} / ${WORKLET_NAME}
  placeholders to stay in src/renderer/src/lib/audio.ts, and the e2e HUD probe
  requires data-hud / data-hud-bar hooks and exactly five buttons in the bar.

11. OPEN ITEMS / FOLLOW-UPS
--------------------------------------------------------------------------------
  - Replace <release-host> and <repository-url> in smog-build-manifest.json
    after publishing (winget, npm global, install.sh bootstrap).
  - macOS (.dmg) and Linux (AppImage/deb) artifacts require building on/for
    those platforms: npm run package:mac | package:linux
  - Windows arm64 installer: npx electron-builder --win --arm64 --publish never
  - Publishing steps (npm publish, winget manifest, release hosting) are not
    performed; artifacts are local under ./release only.
  - Auto-Pilot engine, screen watch/scan and the global shortcuts are exercised
    through typecheck + manual runs; the 31 e2e checks cover the pre-existing
    flows (they predate Phase 2) — extend scripts/e2e.mjs to assert them.
  - System loopback audio is Windows-only (getDisplayMedia audio:'loopback');
    macOS/Linux need a different system-audio capture path.
